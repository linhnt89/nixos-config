# MetaCube NixOS Configuration

- This repository manages MetaCube declaratively with NixOS and Home Manager.
- Keep workstation-wide tools in NixOS/Home Manager and project-specific runtimes in project `devShell`s.
- Inspect Git status and preserve work from parallel branches or worktrees before editing.
- Treehouse pool capacity is declared in the repo-root `treehouse.toml` (`max_trees = 8`) and overrides the user-level default in `home/modules/dev.nix` (`~/.config/treehouse/config.toml`).
- Feature branches validate with `scripts/check.sh` (static checks, `nix flake check`, non-activating toplevel build — never a switch).
- Treat `nixos-rebuild switch` as machine-global; normally switch only from the integrated canonical `main` checkout.
- New files referenced by this Git-backed flake must be Git-visible before Nix can evaluate them.
- Prefer clear module ownership and avoid duplicating configuration across modules.
- Pi authored configuration belongs under `home/pi/`: `models.json`, `AGENTS.md`, and `openai-server-compaction.json` are read-only declarative links; `settings.json` and `web-search.json` are seeds copied once into runtime-owned files (`~/.pi/agent/settings.json`, `~/.config/pi/web-search.json`) on first activation. Pi owns the runtime files afterwards; the tracked clone is never written at runtime. Re-apply tracked defaults with `pi-apply-defaults`. Credentials and runtime state under `~/.pi/agent/` must remain outside Git. See `docs/pi-settings-boundary.md`.
- The MangoWM + Noctalia desktop experiment is gated behind `metacube.experiments.mangoNoctalia.enable` (the host sets it true in `hosts/metacube/configuration.nix` — durable since the captain's Phase 1 manual testing, 2026-08-16; the module option default stays off). While enabled, the greetd default login session is Mango started through UWSM (`modules/nixos/mango-experiment.nix` overrides the `lib.mkDefault` greetd command in `modules/nixos/hyprland.nix`); Hyprland stays installed and selectable from the login screen (tuigreet F3 session menu → "Hyprland (uwsm-managed)"). The conditional-default and UWSM-path boundaries are enforced by assertions in `modules/nixos/mango-experiment.nix` plus `scripts/test-mango-default-session.sh`; runbook and rollback live in `modules/nixos/mango-experiment.nix`, `home/modules/experiment.nix` and `docs/mango-noctalia-experiment.md`. It uses the pinned `nixpkgs-unstable` input (mango/noctalia do not exist on stable).
- The desktop's Home Manager config imports the **desktop role** and the opt-in **firstmateTools module** of the `nixdev-config` flake (`nixdev-config.homeManagerModules.desktop` / `.firstmateTools` in `flake.nix`): the role owns the portable shell/dev layer (zsh/starship/fzf/bat/eza enablement, direnv, delta/git structure, common packages incl. Python/Node, `gh` — never `glab`), and firstmateTools owns the shared Firstmate toolchain (axi CLIs, no-mistakes, treehouse, pinned herdr opt-in via `nixdev.firstmate.enableHerdr`; shared package pins are nixdev-config-owned, this consumer declares no treehouse/herdr/noMistakes inputs and passes only the exported `packages.${system}.treehouse`). Local `home/modules/{shell,git,dev,firstmate-timer}.nix` are personal adapters; keep MetaCube identity, SSH hosts, appearance/apps/services/Waybar/Mango/Noctalia, Pi seed, the user-level treehouse default, the Herdr-backend choice, and the opt-in FM Dependabot sweep timer (`metacube.firstmate.fmDependabotSweep.enable`, MetaCube-only) local. Public input: fetching needs no GitHub token (never commit a credential, and never substitute a `path:` input); updates land via Dependabot, `nix flake lock --update-input nixdev-config`, or the automated narrow lane `scripts/update-nixdev-config.sh` (guarded lock-only bump → `scripts/check.sh` → gh-axi PR → squash merge → canonical fast-forward; never activates; offline regression tests in `scripts/test-update-nixdev-config.sh`; runbook: `docs/updates-runbook.md` → "Automated nixdev-config bump"). The lane's paths are portable with `$HOME` defaults (`$HOME/firstmate/projects/nixos-config` canonical, `$HOME/firstmate/projects/nixdev-config` source) and `NIXDEV_UPDATE_CANONICAL_REPO`/`NIXDEV_UPDATE_NIXDEV_SRC` overrides — never hardcoded home paths. `scripts/check.sh` also evaluates the imported HM user config. See `docs/nixdev-config-integration.md`.
- When giving manual configuration changes, explain the change first and provide complete changed files rather than partial replacement fragments.
- Before considering a configuration change complete, successfully build the relevant NixOS configuration or clearly report why it could not be built.
- Dependency updates land via Dependabot PRs validated locally with `scripts/check.sh` (static checks + `nix flake check` + non-activating toplevel build; CI is an optional `workflow_dispatch` fallback, `.github/`); the PR-to-switch procedure is `docs/updates-runbook.md`, staleness is reported by `scripts/check-stale.sh` (flake inputs only — shared Firstmate toolchain pins are tracked in nixdev-config). Nix-managed tools are never self-updated, `stateVersion` is never bumped during upgrades, and the shared no-mistakes daemon is restarted only by firstmate after a Nix bump.
